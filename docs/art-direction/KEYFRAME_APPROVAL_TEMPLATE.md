# KEYFRAME APPROVAL

Figma is a visual specification surface, not the permanent project source of truth. The repository and PROJECT_WEBSITE_SPEC remain authoritative.

## Purpose

Keyframes establish the approved visual target before full production.

Do not design every page before development. Create only enough approved frames to prove the visual system, responsive strategy, and highest-risk compositions.

## Required Keyframes

For most projects:

- Desktop hero / first viewport
- Mobile hero / first viewport
- One representative content section
- One representative high-expression or signature state
- One conversion / closing state

Add additional keyframes only when they resolve material uncertainty.

## For Each Keyframe Record

- Frame name
- Viewport dimensions
- Page/route
- User state
- Section job
- PRIORITY A1 content
- Dominant visual object
- Typography roles
- Grid/container behavior
- Media/assets used
- Interaction implied
- Responsive relationship
- Reference relationship
- Open questions

## Keyframe Quality Gate

A keyframe passes only when:

- hierarchy is intentional;
- typography is production-quality;
- major imagery/assets are approved or genuinely representative;
- composition belongs in the intended professional quality class;
- the frame clearly expresses the approved art direction;
- spacing and scale feel deliberate rather than templated;
- it does not rely on animation to hide weak static design;
- mobile is independently composed rather than merely scaled down;
- reference-led work has been compared directly with its governing references.

## Approval Status

Use:

- NOT STARTED
- IN DESIGN
- REVIEW
- REVISION REQUIRED
- APPROVED

Full production must not begin from an unapproved visual target when visual design is material to project success.
